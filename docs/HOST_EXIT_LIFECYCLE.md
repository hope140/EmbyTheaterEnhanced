# Host exit lifecycle candidate

This candidate changes only the source-built Windows Host exit route. It keeps the approved one-second preview, SMTC commands, playback pipeline, configuration and installed payload layout unchanged. The existing v0.4.3 tag and installer are preserved.

Electron starts before Host initialization and `Application.Run`. Its `Process.Exited` callback runs without a synchronizing object and previously called `Application.Exit` directly. A request made before a message loop exists can be lost. The candidate captures the main STA Dispatcher before Electron starts, latches the first exit request and queues it to that thread. It exits only when `Application.MessageLoop` is true; a one-shot main-thread Idle handler retains requests that arrive while initialization or a nested non-Forms pump is still running. No timer, force exit, process kill, renderer command or new media pipeline is added. Two fixed log markers identify the application-loop call and return.

`tools/test-host-exit-lifecycle.ps1` extracts the exact selected exit methods from the fixed v0.4.3 source and candidate Git blobs, compiles isolated x86 Framework executables with the Microsoft-signed system compiler, and runs real WinForms/WPF loops with an owned short-lived child. Cases cover exit before the loop, an early nested Dispatcher pump, exit after a real loop tick, and repeated exit. Baseline watchdog cleanup is explicitly a negative regression result; candidate cleanup/timeout cannot pass. The report binds source and method hashes and records compiler/reference identities. No installed client, account, network service or FFI is used.

This source-level regression is not a complete Host or installer acceptance. In particular, it does not establish that the previously observed Host residue has this sole cause. A fresh source-built Host and ordinary package must pass normal startup/close with the corrected checker before release. The Host source fingerprint is updated; old build/verification receipts cannot satisfy the new source gate. `host-retirement.patch` must reproduce the current replacement sources byte for byte. The ordinary builder uses this patch-only route; a mandatory source-chain phase now compares it with `Apply-SourceChanges.ps1` and runs the real identity gate before compilation.

The first full candidate build correctly stopped at identity verification: the old patch still produced the exact v0.4.3 Program bytes (`bbff261a…`), while the declared replacement contained the exit fix (`df2b936e…`). This was a stale patch, not CRLF drift. Only the Program patch section is regenerated; Program source and the already tested exit methods are unchanged. The source-chain regression verifies all55 official inputs, both57-file outputs and46 compile inputs; the old stale-patch combination must fail. No old executable or accepted receipt substitutes for a fresh build.
