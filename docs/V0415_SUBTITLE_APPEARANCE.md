## 范围与参考

2026-11-05 只读核对 Emby 网页端 `app.emby.media/videoosd/videoosd.js`、`modules/subtitleappearancedialog/subtitleappearancedialog.js`、`settings/subtitleappearanceeditor.js` 和编辑器模板：当前网页端从播放字幕菜单进入“字幕外观”弹窗，使用同一用户设置的字号、文字颜色、阴影、背景色和透明度字段；对文本字幕显示入口，ASS/SSA 不走普通外观设置。仅参考行为，没有将该网页端源码或模板纳入仓库。

ETE 沿用现有 `localplayersubtitleappearance3` 设置，在播放 OSD 的字幕菜单添加弹窗。每次选择立即写入当前账号的本机用户设置，并向当前原生 libmpv 代次提交对应属性；关闭弹窗不停止播放。弹窗随字幕轨切换、播放停止、OSD 离开和销毁而关闭。远控播放器及图片字幕不显示入口。现有设置页、字幕搜索、字幕偏移、轨道与会话归属不变。

原生映射沿用已支持的字号、文字颜色、背景色和透明度。为处理播放中清除阴影效果，额外开放 `sub-outline-size`、`sub-shadow-offset` 两个受限属性；`none`、`uniform` 与默认可分别重置，`raised`/`depressed` 只能映射为 libmpv 的相同近似阴影，不能复制浏览器的上下方向叠影。mpv 对 ASS/SSA 和图片字幕不保证应用普通文本样式，因此入口避开这些格式。

## 首轮现场反馈后的界面与数值修正

用户用 `c3f8c73` 验收包确认外观调整在播放中实时生效，但截图显示弹窗为宽约 730px、高约 860px 的蓝色大面板，背景下半部空白，选项混用中英文，默认描边显示为“居中位置”。现仅给该弹窗使用 ETE 播放界面的深色中性表面，宽约 480px、内容自适应高度；保留 Emby 选择器、关闭方式和即时保存。补齐简体／繁体中文色名及透明选项，将本地播放器实际描边效果标为“标准描边／加粗描边／偏移阴影”，并说明两种旧偏移方向在 mpv 中呈现相同近似效果。未修改已保存的阴影值。

字幕字号共有六档：最小 `28`、小 `35`、正常 `38`（mpv 0.41 默认）、大 `65`、更大 `75`、最大 `85`，数值为 mpv `sub-font-size`。历史候选的最小为 `35`、小为 `45`，导致“小”比默认“正常”更大；本次将两档小字号映射为 `28/35`。已保存的 `smaller`、`small` 字符串继续保留，打开弹窗仍显示原档位，但新版播放时实际字号会变小。其余四档数值不变。

文字颜色为 16 个预设十六进制色；背景颜色为透明或相同 16 色；背景不透明度为 10、20、25、30、40、50、60、70、75、80、90、100%，透明背景时不显示该选择器。描边／阴影为关闭、标准描边、加粗描边和两个历史偏移选项。入口仅在本机播放且当前选中普通文本字幕时显示；SRT/SubRip、WebVTT、mov_text、text、TTML 可用，ASS/SSA、PGS、VobSub 等图片或自身带样式格式不显示。播放器只提供原生 mpv 能实现的近似外观；不提供字体族、字重、行距、任意颜色或垂直位置的播放中编辑。设置写入当前账号本机用户偏好，换到远控播放器不应用此控制。

## 字幕菜单视觉统一（后续修正）

后续双图对照确认旧字幕选轨菜单使用 `dialog-blur` 半透明表面，而上一版外观表单使用不透明深灰底和独立标题栏。现复用既有主题模糊类及圆角，去掉局部背景变量，标题居中、左侧保留返回，表单宽度 `min(80vw, 60ch)`、高度上限 `84vh`；窄窗左右保留 8px。字段和实时应用不变，公共菜单源码未修改。

运行 `node tools/check-subtitle-appearance-renderer.cjs <绝对 Chromium 路径>` 可复验；设置 `ETE_SCREENSHOT_PATH` 可输出普通及 `-narrow` 截图。该探针使用冻结主题／字体、真实弹窗模块与合成组件宿主／播放器，验证两个窗口尺寸、透明表面／标题位置、CSS 迟加载、滚动末项、键盘与鼠标关闭、重开、保存与即时应用调用。Windows Native、真实视频、遥控及完整客户端尚未测试。前述 480px 深灰样式为历史阶段，本节取代其当前视觉规格。

## 验证与验收

用户首轮验收反馈“点字幕外观后完全没有弹窗”。调查确认菜单触发的全局 Alameda `require` 使用 `www/index.html` 所在目录解析 `.js` URL；首轮代码误以 `videoosd` 模块目录为基准，实际请求 `../../enhanced/...`，落到不存在的位置。已改为从 `www` 起算的 `../enhanced/...`。新增隔离点击测试：加载仓库冻结的 Alameda、执行实际补丁生成的菜单分支、按打包文档 URL 读取真实弹窗模块，并断言打开五字段弹窗；同时断言旧路径不存在。用户随后在真实客户端确认弹窗和设置即时生效。

- 本地 Node 定向测试覆盖设置转换、当前播放即时写入、默认恢复、停止后拒绝旧写入和下一次播放取持久设置；构建输入与 Web overlay 的固定源哈希约束继续验证。
- 隔离 Chromium 加载真实弹窗源码和冻结主题 CSS 验证五字段、简体中文标签、480px 紧凑布局、窄窗口、鼠标选择、键盘改值、即时保存／应用、透明背景时隐藏透明度以及关闭收尾。原生设置单测断言两档小字号与正常档的正确顺序。这不是完整客户端的视觉或实际字幕渲染验收。
- 待新 Windows 构建和真实客户端复验：确认深色弹窗与 OSD 协调、中文文案、五档描边近似、小字号顺序，以及鼠标／键盘／遥控焦点；更改后观察当前画面和重新播放。ASS/SSA、PGS 不应出现入口。用户 NAS 与实际字幕素材未由本开发环境访问。
