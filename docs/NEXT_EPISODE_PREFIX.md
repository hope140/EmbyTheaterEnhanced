# 独立下一集预载候选

普通设置中的“下一集预载”默认关闭。启用后，在下一次播放安全应用，不要求重启、不打断当前播放。阈值可选 50/60/70/80/90%，默认 70%；预载媒体预算 P 可选 100/300/500 MB，默认 300 MB（十进制）。没有额外的总盘容量或后台限速必填项。最后播放缓冲持久化仍是[独立可行性研究](PLAYBACK_BUFFER_RETENTION_DESIGN.md)，本功能不提供它。

## 数据与预算

`playback-range-session.js` 的 `kind: next-prefix` 使用 `playback-prefix-store.js`。P 直接从已确认的 `preloadMB` 派生，不读取旧实验的 `maxBytes`。同一 store 中所有候选、正在接管的前缀及写入媒体数据合计不超过 P；没有每个视频各一份 P。普通目录固定为所选profile下的 `next-episode-prefix-v1`，独立于Electron HTTP/page缓存及旧range实验。索引只在进程内，磁盘只有有界媒体块和固定所有权标记，不保存 token、URL、账户明文或最后播放索引。

前台对当前视频的读取只命中已预载部分或透传来源，不保存新字节。新的下一集候选可回收已经接管的旧前缀；旧播放路由继续有效，缺块回源。串行文件读取完成后才删除所属块，不删除另一个进程的数据。写入先完成临时文件并关闭，再提交；中断写入不成为可读块。启动获得独占所有权后清除前一进程遗留的预载，正常关闭等待读取/写入/租约释放后删除所有媒体块。不会跨进程恢复前缀。

预热从原始字节零开始，最多 P 或文件长度，允许不足一块的尾部。它不保证对应固定播放秒数；容器尾部索引可能仍需前台获取。单字节来源校验是控制开销；媒体预载尝试的预算包含中断尝试，抢占后可能只得到部分前缀，界面如实显示部分/不可用。前台透传所需数据不属于后台预载量，也不增加磁盘预载。

## 播放与来源边界

原 PlaybackManager/队列、MediaSource、PlaySession 和实际播放事件归属保持。维护 renderer 只读取明确的同系列 Episode 邻项；实际播放开始后，renderer 的进度与 main 的 helper 属性都达到阈值才允许预载。未确认或多个媒体版本跳过，不调用 nextItem 来猜测下一集，不触发自动播放。原连播和用户手动下一集仍由原 owner 决定。

Stop/换代取消下载并退休路由，已提交下一集前缀可用于同进程的正常 Stop→begin-generation→实际下一集交接。新的来源仍需重新验证授权/表示；不同服务器、账号、媒体版本、ETag 或长度不混用。实际开始接管后，前缀是可丢弃的预载数据，不升级成最后播放缓存。候选更换、身份变化、明确取消或应用退出清理未播放预载。

只支持可验证的同源静态 HTTP(S)、精确 206、强 ETag、已知且稳定长度；不转发未知敏感头、不跟随302或跨域跳转。当前来源无法受该层观察时不启动后台预载，继续原播放。dian115/302、Cookie/Header 鉴权、转码及直播不在已验证范围。首次资格失败沿原 source；已选路由发生版本变化则拒绝混合字节，不宣称无缝故障切换。

后台媒体与探测只有一个请求槽。前台缺块中断后台，并等待实际请求关闭后才回源；取消的前台等待不会随后偷偷发请求。无需用户填写 MB/s，但这不是系统级网络 QoS 或零缓冲保证。

## 验证层次

Node 回归使用临时根目录、合成身份和小型 loopback 字节。设置测试验证真实 100/300/500 MB 映射；低层预算测试仅替换 policy 的结果为 17 字节，真实执行存储与 HTTP 代码，验证总占用、末块、前台不累计、跨账号不命中、抢占、物理取消和退出清空。API/队列集成仍明确使用替身 helper，不能计作 Windows 自动播放通过。独立真实 Alameda 回归已通过原 renderer 定时器与原 manager 的 stopped/nextTrack 自动交接，另测原队列移除候选与应用退出清空；helper 时钟、document 和定时器压缩仍为替身，未证明固定 Windows helper 解码。

真实 helper 自动链须在另行协调的隔离 Windows 环境执行：真实 helper 进度→维护 renderer 定时器→阈值预载；A 自然 EOF→原 PlaybackManager stopped/nextTrack→B 真实加载解码并读取预载块。测试只能一次调用原 manager.play，不能人工调用 preload、tick、nextTrack 或伪造 EOF。隐藏显示层的替代、候选/overlay 身份、固定 DLL、来源请求、命中、解码和所属进程退出须单独记证据。脚本准备及 Node 结构检查不代表该链已运行。
