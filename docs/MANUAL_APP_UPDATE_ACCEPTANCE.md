# 手动更新优化：独立验收

PR #79 保持未合 main。目标程序启动时调用清理入口，读取当前实际版本及受管记录；因此目标也必须包含该入口。同一 Windows 用户/profile、同一实际 executable 位置、版本达到记录目标以及文件身份验证缺一不可。旧更新进程退出或安装向导完成均不能替代这次启动确认。

## 两个真实版本与产物

- 起点 A：历史候选 `7d624bcfb4db44e47d73c36433f42056d3bfff4d`，真实产品版本0.4.3，既有独立构建 [40170353775](https://github.com/hope140/EmbyTheaterEnhanced/actions/runs/40170353775)。若已有经过manifest及完整SHA核验的副本可复用；远端artifact到期不使已核验副本失效。仅在没有可用副本时按该准确源码重建，不从较新源码下调版本。
- 官方目标 O：本次主线v0.4.4，最终main／tag为 `b6fe06b984d74f60bdf82527d0666e920449dedb`。只有发布流程完成且官方API五附件及安装附件校验身份齐备后才做下载验收；tag存在不代表附件已就绪。
- 独立目标 B：已从 O 的最终发布提交同步 PR79 功能，仍仅保留于独立feature/draft PR。继承该真实基线版本，文件名标记独立测试与准确SHA，使用新run/artifact；不覆盖 O 的附件或已有artifact。B 必须包含启动清理入口及包内9项/12模块绑定。

不创建假较低版本、不改生产API/Tag/下载规则、不加入本地假feed、自定义URL或跳过官方校验。Actions artifact不是生产更新源；它只能供明确的人工安装验收。

## 用户最短操作

1. 由用户在已授权覆盖的测试安装上操作，保持同一Windows用户、安装目录和profile；先保存程序/profile备份并核对 A/B 各自的manifest、准确SHA及安装器完整哈希。助手不在Work现用客户端运行或安装。只有需要保护其它现用安装或无法可靠保留测试状态时才改用VM/独立测试用户；profile使用appData，若选择隔离，单独的`--user-data-dir`不足以隔离。安装器需要管理员权限，正常UAC由用户亲自核对并决定；明确的SmartScreen拦截或策略拒绝则记录原文并停止，不强制继续、不更换执行入口、不关闭防护。
2. 安装 A。O 确已发布且高于 A 后，手动选择测试通道、点击检查及下载。验证无保存目录选择、进度、取消/重试；成功时应先正常退出Electron与同目录Host，再出现系统安装/安全界面。用户手动完成 O 安装并启动。O 若没有 PR79，受管安装包未清理是本阶段预期，不记为清理通过。
3. 保存这一安装状态和受管记录，正常关闭 O。在同一用户、同一安装目录人工安装 B，保留profile，首次启动 B。确认运行版本达到记录目标、来源显示 B 的准确SHA，只清对应受管安装包/临时文件/receipt；Downloads手动文件不变。这里清理的是A下载并登记的官方O安装包；人工下载的B安装器本身不登记、不清理，保留是预期。现有安装器允许等版本文件覆盖，但目录和进程/文件占用门禁仍保留。该步为人工安装后的首次启动清理验证，不能写成 A 自动下载了 B。
4. 在有可恢复的测试状态时另行验证取消向导或拒绝正常确认后重开旧版：好包保留，后续明确点击须再核官方身份才能复用。路径变更、未知文件、篡改或忙碌文件保留，不能为凑通过手工清除它们。

记录结果至少包含：A/O/B各自版本和源码/包身份、实际安装位置及同profile条件、两个应用进程退出时序、提示正文及用户决定、安装前后受管文件清单/身份、首次启动版本、Downloads对照。不要收集账户凭据或真实媒体数据。

## 连续闭环仍需独立结论

本次已选择分段验收，不新增较高官方prerelease，不替换0.4.4资产。上述步骤验证官方检查/下载/退出/安装及新目标首次启动清理；因为B是人工安装，不能写成连续的一键闭环。Actions artifact不接入现有官方更新源，连续链仍保留待验界线。PR79继续保持draft，不为打通验收而先合main。

## 自动门禁边界

本地/Windows缓存用例以新store实例读取持久记录，验证目标启动不依赖源进程内存。夹具版本/发布身份和不可执行文件均明确合成，不表示实际产品安装。Windows自动job继续仅运行原生文件句柄、缓存与marker-only生命周期子集；先前ShellExecute可见窗口/SmartScreen观察保留为交互待验，不自动重试。构建只准备包，不安装、不接受UAC、不退出用户客户端。
