# 用户指南

## 选择版本与校验下载

版本与下载入口集中在[项目首页](../README.md#下载安装)。截至 2026-10-30，正式版为 v0.4.0，最新测试版为 v0.4.6，两者均面向 Windows x64。测试版含较新的功能，适合愿意试用并反馈的用户。

从同一个 Release 下载 `.exe` 与对应 `.exe.sha256` 文件；`Source code` 压缩包用于源码，不是客户端安装包。将两个文件放在同一目录，在该目录打开 PowerShell。以 v0.4.6 为例：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\EmbyTheaterEnhanced-0.4.6-win-x64-setup.exe'
Get-Content -LiteralPath '.\EmbyTheaterEnhanced-0.4.6-win-x64-setup.exe.sha256'
```

比较第一条命令的 `Hash` 与校验文件里的 64 位十六进制值，大小写不影响比较。选择其他版本时使用该版实际文件名。哈希不一致时停止安装并重新核对下载；哈希一致仅说明文件与发布校验值相符。安装包未签名，Windows 可能显示未知发布者提示。

## 手动检查更新与通道

v0.4.2 起，在设置菜单打开“关于 Enhanced”，选择正式／测试通道，待页面提示“更新通道已保存”后，主动点击“检查更新”。正式通道读取 Latest 正式版，测试通道包含预发布版本；保存通道不会自动开始检查。应用不会在后台自动检查、静默安装或提供降级下载。

发现更高版本后，可查看说明并主动下载，说明中的网页链接由系统浏览器打开。版本相同或较低时不会提供下载；例如从 v0.4.5 切回正式通道，不会降级到 v0.4.0。

| 当前正在运行的客户端 | 下载校验完成后的行为 |
| --- | --- |
| v0.4.2–v0.4.4 | 保存安装包，需自行正常退出客户端并运行安装包。升级目标为 v0.4.5 也仍沿用这个旧流程。 |
| v0.4.5 起 | 安装包保存在 ETE 用户资料目录的专用更新缓存；校验及交接准备成功后正常退出客户端，退出后打开安装向导，由用户完成安装。重试会重新核对官方附件身份和已有文件，可复用仍有效的安装包。 |

v0.4.5 的“下载更新”会在成功后进入退出与安装交接，开始前请保存当前工作；交接提交前可以取消下载。向导仍可拒绝或取消，应用不会代替用户完成安装。普通播放媒体的提前下载和跨重启续传属于另一项尚未发布的功能，与软件更新缓存不同。

v0.4.0 及更早版本可直接从项目 Release 下载目标版本并按下节升级。检查或下载失败时，也可使用这个入口，核对版本和校验文件后安装；不要用第三方同名包替代。

## 安装与升级

1. 保存播放状态，正常退出客户端。
2. 升级前备份重要配置。备份 `%APPDATA%\EmbyTheaterEnhanced`，以及存在时的 `%APPDATA%\Emby Theater Enhanced`；若自行指定了其他用户资料目录，也需备份该目录。仅复制程序安装目录不能完整备份用户资料。备份可能含登录资料和 Token，请只保存在可信的本地位置。
3. 运行已校验的安装包，按管理员权限提示选择语言和安装目录。升级会预填已有安装位置，请确认原目录。
4. 安装完成后启动客户端，在“关于 Enhanced”确认版本；首次使用时连接自己的 Emby 服务器。

安装器会检查目标目录中的客户端及被占用文件，不会替你强行结束进程。若被拒绝，正常退出客户端后重试。复制或替换失败时保留错误信息，检查目录权限与剩余空间，再在原目录重试；必要时使用此前可信的安装包恢复。安装器不提供自动回滚。

## 卸载与资料保留

正常退出客户端后，在 Windows“设置”的应用列表中找到 Emby Theater Enhanced 并选择卸载，按向导完成。当前安装器卸载程序组件时保留个人设置、登录资料和 DeviceId；卸载后重装会继续使用保留资料，并非恢复全部默认设置。重要配置仍应先备份。

安装、升级与卸载的已验证场景有明确边界，不能保证所有权限、取消、失败恢复和首次启动组合；见[已知问题](KNOWN_ISSUES.md)及[v0.3.9 安装核验](V039_RELEASE_VERIFICATION.md)。v0.3.11 的包体核验没有追加系统安装场景。

## STRM 与 CloudDrive2

启动后使用自己的 Emby 服务器登录。普通媒体无需配置 STRM 增强。在设置菜单打开“智能解析”（旧版显示“STRM 智能解析”），启用所需解析方式。

CloudDrive2 地址填写当前服务地址，Token 通过单独设置动作保存；连接测试使用已保存地址和 Token。Token 不从设置读取接口返回。保存地址后测试连接，再填写路径规则，保存后重启生效。

假设 Emby 的 Item.Path 为 /library/Example.strm，MediaSource.Path 为 /media/cloud/Movies/Example.mkv，而 CD2 中该文件为 /drive/Movies/Example.mkv：sourcePrefix 应是 /media/cloud，cloudPrefix 应是 /drive。可选 mountPrefix 是当前电脑能访问的挂载目录，例如 X:\Cloud；它与服务器路径、CD2 路径不是同一个位置。

规则使用最长前缀且必须匹配目录边界。cloud-first 依次尝试 DirectUrl、CD2 HTTP、Mount、Native；mount-first 优先本地挂载；custom 按页面顺序。无法确定 cloud 或 mount 前缀时不要猜测。先在 CD2 确认目标文件，使用规则测试验证映射。

智能映射助手输入同一媒体的 STRM 目标路径、CD2 文件路径和可选本机挂载路径；使用两个不同目录样本确认映射边界。建议加入的是草稿，仍需点击“保存设置”；离开页面不自动保存，也不会扫描网盘。

播放失败时查看诊断中的路由和 cd2Reason：mapping_miss 表示没有可用映射；not_found 表示服务返回找不到；timeout 表示预算耗尽；invalid_file 表示响应不符合文件检查。当前仅在目标资源明确返回 NOT_FOUND 时进行有限的父目录刷新并最多重查一次；映射缺失、超时和鉴权失败等不触发该恢复。恢复后仍失败时，请确认 CD2 中的实际资源和映射，其他错误不要当作目录缓存缺失。

## mpv 内核候选管理

“关于 Enhanced”的内核管理区域显示当前进程和下次启动的选择。先准备包含 `candidate.json`、`mpv-1.dll`、`SOURCE.txt`、`NOTICE.txt` 四个固定条目的完整 ZIP，再点击“导入内核包”。维护者可用仓库的 `tools/package-mpv-kernel-candidate.cjs` 生成并验证包；DLL、来源和notice文件需自行提供，工具不会下载内核。

导入会校验包体哈希、Windows x64 DLL结构和必需导出，成功后只加入候选列表。点击“下次启动使用此候选”，退出并重新打开应用后才生效；导入或选择不会切换当前进程的内核。选择固定基线也同样在下次启动生效。

候选启动验证失败时，应用在失败进程退出后至多回到固定基线一次；基线仍失败则停止重试。候选已运行后的故障不会触发进程内换库。静态校验和Helper握手不代表DLL实际加载映像哈希、来源声明或许可已经独立核验，界面保留相应UNKNOWN/未评估状态。缺少可信来源元数据或候选存储不可用时，按页面原因处理，不绕过校验手动覆盖程序目录。

## 缓存管理

v0.4.2 起，在设置菜单打开“缓存管理”，可查看资源缓存和页面缓存，分别清理或一并清理。资源缓存显示 HTTP 缓存总量，不能理解为海报独占大小；清理后可能随浏览重新增长。页面缓存包括有限页面数据，详情缓存先展示标题、简介、海报等静态内容，再更新服务器数据。

清理保留登录和设置，不删除媒体文件，也不清理播放器缓冲或 mpv 内核。缓存不代替服务器授权、最新进度或播放数据，网络失败时不能依靠旧详情缓存直接播放。

## Windows 媒体控制与预览

v0.4.3 普通安装即可使用 Windows 系统媒体卡片和任务栏视频预览，无需实验环境变量或专用启动脚本。系统媒体卡片控制播放／暂停、停止和队列上一项／下一项，后两项按实际队列可用性启用；卡片布局由 Windows 决定，停止不一定显示独立图标。

任务栏缩略图和 Peek 使用一秒采样的视频画面，是低频截图，不是连续视频，也不合成字幕。切换媒体、停止和退出时会清理所属画面。原任务栏缩略图下面的播放／暂停与停止两个按钮已移除，改用系统媒体卡片。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 找不到缓存管理、更新通道或系统媒体预览？ | 先在“关于 Enhanced”确认版本：前两项从 v0.4.2 起提供，系统媒体集成从 v0.4.3 起提供；正式版 v0.4.0 不含这些新增功能。 |
| 切到正式通道后没有下载按钮？ | 更新器只提供更高版本；测试版可能高于当前正式版。通道选择不会触发降级。 |
| 缓存清理后又增长、大小不等于播放器占用？ | HTTP 缓存会重新产生；统计不涵盖全部内存、解码资源或视频缓冲。 |
| 任务栏没有原来的控制按钮，预览没有字幕？ | v0.4.3 已移除原两个按钮；使用系统媒体卡片。预览不合成字幕，也不承诺流畅视频。 |
| STRM 播放失败？ | 先确认服务器可播放、CD2 中存在文件，再检查已保存的连接和路径映射；按上文配置步骤与[已知问题](KNOWN_ISSUES.md)排查。 |
| 是否支持下一集预加载、缓冲暂存或飞牛认证？ | 尚未发布，分别处于[独立实验阶段](NEXT_RELEASE_SCOPE.md#未发布实验)，不应作为当前安装包的可用功能。 |

## Anime4K 资源与快捷键兼容

旧版 Ctrl+0、Ctrl+反引号和 Ctrl+1 不再由 ETE 截获，也不会重命名 mpv 全局目录里的 Anime4K 配置或停止当前播放。本版本不重新分配这些按键，键盘输入交由 Emby/Electron 原有处理。已有配置文件保持原样。新包不再附送 Anime4K 的39份 shader，也不恢复旧 mpv 预设。如果个人 mpv 配置引用应用目录内的 `external/Anime4K/shaders/`，干净安装或用户自行移除旧文件后这些引用会失效，可能产生缺少 shader 的错误；请自行管理个人 shader 与引用路径。构建和安装器不会修改个人配置，也不会自动清扫旧安装目录中的这批文件。

## 旧外置播放器连播兼容

详情页的旧外置播放器按钮和它的连播计时器已停用，相关设置会保留且不会自动改写。需要 Emby 自动播放下一集时，请继续使用播放设置中的“自动播放下一集”；该流程仍由正常播放队列管理。

## 问题反馈

1. 在“关于 Enhanced”记录应用版本；说明 Windows 版本、普通媒体或 STRM、预期行为与实际现象。
2. 记下发生时间和时区，以及最少复现步骤。播放问题补充是否使用 CD2 或本地挂载、是否发生在切集、停止或切换字幕/音轨时。
3. 在设置的“诊断与日志”点击“导出诊断日志”，保存 TXT。无法启动或无法导出时，先说明该情况并保留错误文字。
4. 检查导出内容，隐藏账号、Token、Cookie、完整媒体地址、私人路径及媒体库标识，再到 [GitHub Issues](https://github.com/hope140/EmbyTheaterEnhanced/issues)提交问题和必要片段。不要上传整个用户资料备份。

日志中的 `UNKNOWN` 表示缺少相应证据，不等同于失败。详细字段和可选仓库采集工具见[诊断说明](CLIENT_DIAGNOSTICS.md)；配置技术边界见[配置合同](STRM_RESOLVER_SETTINGS.md)，当前限制见[已知问题](KNOWN_ISSUES.md)。

## 完整提前下载（独立候选，尚未发布）

服务器在线时使用影片原来的“下载”按钮。首次选择保存目录后会记住；“设置 → 下载”可更改默认目录、查看进度和失败原因或继续任务。新任务使用新目录，已有任务和文件保持原位置。完整文件不随预载／暂存清理，也不会自动接管以前下载的文件。

关闭客户端停止传输并保存任务，下次打开并登录对应服务器账户后继续。能否接着下载取决于来源是否支持安全Range、强校验器，以及原文件是否仍相同；无法安全续传会提示并从头下载该未完成文件。因此STRM／CD2能播放不代表一定能下载或续传。Windows候选已增加不依赖硬链接且禁止覆盖同名文件的提交路径，实际FAT／exFAT仍待验证；FAT32本身无法保存超出其单文件大小限制的影片。目录或文件身份无法安全核验时停止并保留文件。

完成后在ETE播放同版本影片时优先使用已核验的本地文件，仍需服务器在线核权。需要断网播放可自行去下载目录打开普通视频文件；本功能不提供离线登录、浏览或外部字幕同步。
