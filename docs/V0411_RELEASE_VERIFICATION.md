## 集成与发布停点

先在独立非保护分支提交、推送并以 PR 运行准确源码的公开和隔离 Windows CI，核验标准发行构建和附件字节。用户确认本次 main 合并影响后，核对 main 未漂移，再经普通 PR 合入或获准的正常快进；从最终产品提交重新核对必要门禁。仅随后创建未占用的 `v0.4.11` Tag，固定被 main 包含的同一 source。按既有 `Manual verified release` 以 `channel=testing`、`expected_latest_tag=v0.4.0` 和准确成功的标准构建 run 执行；它不创建或移动 Tag，测试渠道须保持正式 Latest 对象不变。发布后独立回读五附件、provenance、校验文件、原始 notes、渠道及 Latest；出现失败或未知结果先回读对象，不覆盖旧发布。

从旧版升级至 0.4.11 时运行旧版退出逻辑。要验收 0.4.11 的更新交接，必须先运行 0.4.11 客户端，并在之后提供高于 0.4.11 的有效测试版本，再由 0.4.11 发起升级；该后续版本需单独决定、构建与发布，不以一步升级声称通过。
