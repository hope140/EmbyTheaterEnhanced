# FN认证：当前决策结论

建议保留默认关闭的独立原型，下一步只验证真实官方授权与既有Emby映射；不新增FPK、Docker组件或Emby插件，也不把原型并入正式功能。现有服务端映射已经解决，客户端必须保留 `FN映射 → dian115代理 → Emby`，不能改为直连Emby绕开代理。

| 问题 | 可据此决策的结论 |
| --- | --- |
| 已证明什么 | 固定Electron44.4.2、正常沙箱下，真实内存Session配本机合成网关连续两轮通过。HTTP Cookie、连接隔离、Range/206/416、本机媒体桥、302凭据隔离、WS字节桥、取消、合成过期及关闭清理均在严格门禁中。81项本机FN测试通过。 |
| 真实NAS还缺什么 | 官方页面实际跳转、授权门及Cookie作用域/有效期/撤销语义；认证后同Session是否能读到正确Emby公开信息；dian115的真实媒体302、字幕、转码、WS及中继/直链流量路径。两轮合成通过不回答这些问题。 |
| 什么时候认证 | 用户主动添加FN服务器时，先在正规页面自行认证，再验证Emby公开信息，然后继续原Emby账号登录。不能等到首次播放才发现尚未授权。 |
| 会话如何隔离 | 每个连接实例独立内存Session；同NAS不同账号也不共享。已有效会话复用，仅明确FN挑战才重新提示；普通Emby401/403及网络错误不能直接判为FN过期。切换身份/删除连接时退休该连接请求并清会话。不存NAS明文密码，不复制系统浏览器令牌，暂不承诺跨重启免登。 |
| Native最小接线 | API绑定同一连接Session；同源媒体请求由main持有认证，Native只拿绑定连接/来源/代次的127.0.0.1 opaque lease。保留PlaybackManager原Session/PlaySession/媒体归属，Stop/取消/切换时退休所属流。对允许的第三方302只交出无FN/Emby头的地址，禁止玩家全局认证头；不引入缓存策略。生产接线和libmpv实播尚未实现/验收。 |
| 明确不支持的来源 | HLS/DASH及其分片/密钥/多源重写；未经确认允许的第三方302、含已知认证值的外链；需借用第三方客户端签名或未公开协议的来源。WS需要代理时当前拒绝，不绕过代理直连。 |
| 尚未验证、不能宣传支持 | 真实FN HTTPS/跨域Cookie、真实Emby字幕/转码/WS、Native Helper/libmpv播放、中继切换和实际带宽。302后媒体是否继续经过FN，必须实测，不能从入口域名推断。 |

FNID/正常入口地址仍需用户提供或通过正规流程发现，不能只凭账号密码猜测设备。认证由官方页面处理账号类型、2FA和访问码；FN传输认证不替代Emby账号或媒体权限，不建立用户映射。
