# 原生预览550ms试验

默认采样预算保持1000ms，原生试验默认关闭。仅显式设置
ETE_WINDOWS_PREVIEW_INTERVAL_MS=550 才选择较快档；
ETE_WINDOWS_PREVIEW_BASELINE=1 优先恢复原预算。变量只由新进程继承。

较快档要求已有当前媒体有效帧、播放未暂停，并在最近2.5秒收到DWM请求。
需求租约不代表预览持续可见；隐藏或最小化仍跳过采集。
JS冷却和helper硬下限均为500ms，目标约1.8次采样/秒，
最多2次/秒，不代表屏幕呈现帧率。维持单并发、媒体归属和退役检查。

RPC超过100ms、NativeImage建立超过8ms，或同步DWM请求处理超过20ms，
退回低频30秒。暂停、无需求和首帧限制保持；旧媒体迟到回复不能改变
当前媒体的退回状态。阈值只限制工作预算，不证明CPU或GPU成本低。

手动云验证选择 native_preview_pacing_only=true，其余选项全部false。
使用固定Electron、libmpv及工具链，只编译helper包装程序，不重编内核，
不生成安装包。先通过既有生命周期、helper握手及所属退出检查，再以
相同720p合成片源、相同窗口分别执行1000ms和550ms串行采样。

每组预热后测量10秒，记录有效回复间隔、变化次数、RPC及Native阶段耗时。
只读测量所属helper的CPU时间和内存；不可用明确标记UNAVAILABLE。
两组片源SHA必须相同，退出和报告scope严格校验。
只保存测量及进程诊断，不上传合成视频或profile。

该短验证直接调用helper，不覆盖main自适应调度、NativeImage或DWM提交。
helper CPU不是整个应用或GPU成本；单次固定顺序对照不能证明用户体验改善。

已完成公开回归：1671通过、11跳过、0失败。
定向回归：85通过、1跳过、0失败。
C++提取源码40项及JS、PowerShell语法检查通过；WinAPI和截图节点使用替身。
真实Windows编译、性能测量及任务栏呈现效果尚未验证。


加载门禁失败时，云日志输出固定NATIVE_LOADER_CHILD事件：A/B阶段、退出码、
允许列表内的启动错误码、15秒超时标志、报告是否存在及有界内部阶段。
阶段区分目标哈希、C#互操作编译、DLL加载、依赖检查、释放和报告写入；
只有固定枚举、数值及布尔值进入日志，不回放原始子进程输出或异常路径。
NATIVE_LOADER_FAILED保留失败状态；原15秒限制、0x1100加载flags、固定输入、
FreeLibrary及严格A/B评估保持。诊断输出失败不能阻断原释放。
本地受控子进程验证超时、启动失败和脚本失败；提取的实际PowerShell阶段
写入函数及嵌入C#可验证，但不能代替Windows DLL加载。
加载首因或性能结果缺少直接证据时仍保持未知，不跳过加载门禁。
