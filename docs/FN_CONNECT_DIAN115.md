# FNConnect 接入 dian115 代理链

当前默认链路为 **ETE → FNConnect/fnOS 网关 → 伴随应用 → dian115 的 Emby 代理入口 → Emby**。伴随应用的唯一上游是 dian115 代理，不是 Emby 原生入口，也不是 dian115 管理后台。不配置直连 Emby 回退，不把连接失败变成绕过代理。本方案仅补 FNConnect 接入，不改 dian115、Emby、媒体库或现有播放策略，不实现缓存。

## 已知边界及公开证据

适配目标是 Docker Emby、Host 网络模式的 dian115 代理场景；端口、监听地址、路径和版本均须显式确认。Host 网络模式本身不能证明某个默认端口或 loopback 地址可用，不能推导容器名是应用上游。

已核对项目自己的 [README，固定 commit 3d237581ccc2f1874de915085e4412344cef3c43](https://github.com/madbrolab/dian115/blob/3d237581ccc2f1874de915085e4412344cef3c43/README.md)。作者说明主程序采用私有授权，公开仓库提供文档及规则；部署说明区分 Web 管理、Emby 代理等各自入口，并支持 Host 网络。文档中的示例端口不是本任务的配置。该资料尚不能证明目标版本的 Range、Location、字幕、转码和 WebSocket 行为；没有下载或执行镜像、逆向主程序、获取激活/云盘凭据或联系作者。

## 最小组件的约束

- FPK 候选只注册自己的网关路径和 Unix socket；保持正常 fnOS 认证与原 Emby 登录分离。不安装 Emby 插件，不读取 Docker socket、dian115 数据库、云盘账号或挂载目录。
- 唯一目标是用户已使用的 **dian115 Emby 代理实例**，协议、地址、端口和路径没有默认值。管理页可能可以打开，也不能替代确认该代理入口。
- API、登录、媒体初始请求、字幕、转码及 WebSocket 都先走这个代理实例。不修改原 Item/MediaSource/PlaySession/Session 归属，不新增解析器或失败后直连 Emby 逻辑。
- 若 dian115 原本通过重定向决定实际媒体数据去向，这和客户端自行绕过 dian115 是两件事。是否保留以及怎样保持该决策，须确认实际行为；不擅自改成全流量中继，也不自行生成直链。
- FNConnect 的 Cookie/访问码和身份头不能作为 Emby/dian115 的用户映射，也不能泄漏到媒体外域。原 Emby 请求认证需按已验证合同保留；dian115 是否依赖 Cookie、Host/Origin 或转发头，仍待验证，不能从本地过滤策略推定兼容。

## 必须验证的协议矩阵

| 链路 | 保留边界 | 尚待真实验证；失败时不绕过 |
| --- | --- | --- |
| API/登录 | 原方法、查询、请求体和独立 Emby 认证；401/403 原样失败 | 经 dian115 代理返回的是预期服务器；不把管理登录页/HTML 200 当 Emby 成功 |
| 媒体重定向 | 原状态码和 dian115 决定的目标；适配器不自动跟随或改写未知 Location | 相对路径、根路径、同代理绝对 URL、外域 URL、301/302/307/308 和多跳；目标中是否泄漏内网地址/直接 Emby。未知目标不得由 ETE 自行追加网关/Emby 凭据；含既有签名的 URL 不写日志 |
| PlaybackInfo / 绝对 URL | 不盲目重写 JSON 或替换 source identity | DirectStreamUrl、TranscodingUrl、字幕 URL 是否指向 dian115、原生 Emby 或外域；绝对 URL 不能因“能连上”就跳过代理。原生 libmpv 会独立发请求，不能假定共享浏览器授权 |
| Range / seek | Range、If-Range、206、Content-Range、416 和实际字节 | 代理直出与重定向后分别测试前/中/尾片段、前后 seek、取消；API 200 不证明媒体寻址正常 |
| 字幕 | 原字幕选择、路径/查询、文本/二进制类型及认证 | 外挂/内封提取的请求是否经代理；绝对字幕链接、重定向和编码需单独验收 |
| 转码 | 原 PlaybackInfo、会话和停止归属，不重放 POST | HLS/DASH 清单、相对/根/绝对分片与字幕引用是否仍经有效网关/dian115 路径；未验证前不追加任意响应体重写 |
| WebSocket | 原 `/socket` 所属会话，101 后双向帧和关闭/心跳 | dian115 是否支持该路径升级及 fnOS 网关是否完整转发；不能失败后连接 Emby 原生端口，也不重建 PlaybackManager/Session 来掩盖失败 |

当前 `responsePolicy.redirects=manual-unverified`、绝对媒体 URL 为 `unverified`。本地 HTTP harness 只返回 Location，不会自己请求该 URL；这**不保证未来 ETE/浏览器/libmpv 不自动跟随**。真实策略和窄接线未确定，因此生产功能仍关闭。

## 本轮可执行准备

mock 配置已将上游标记为 `dian115-emby-proxy`，`preserveChain=true`，并明确 `directEmbyFallback=false`；严格配置校验拒绝换成直连 Emby 或开启回退。没有添加真实端口、主机、凭据或 NAS 配置。

新增本地 Unix I/O 双层替身：伴随 harness 只能到 dian115 fixture，fixture 再到独立 Emby fixture。测试核对 API、字幕和转码样例都先经过代理，代理产生的302原样返回且不被内部跟随。它与既有 Range、401、101/合成帧及断流取消测试一起验证 ETE 本地转发边界；**没有证明真实 dian115 的这些功能或已打通 FNConnect**。全部 fixture 是本任务临时目录内的自有 socket，不新增 TCP 端口。

## 最少需要确认的字段

现场只读检查已确认的字段应沿用，不重复要求用户提供；设备地址、端口、版本和原始检查记录保存在仓库外。剩余范围以管理UI能展示的业务状态/应用映射及后续合法媒体行为为限，见下节。以下列表作为首次接入的字段定义保留，不表示当前每项仍未知。

先由用户自己查看现有页面/配置即可，不需要授权助手登录 NAS：

1. **当前客户端使用的 dian115 Emby 代理入口**：协议、主机表示、实际监听端口及路径前缀；不是管理后台地址。去除用户名密码、token/query 和分享凭据，只提供连接字段，不提供整份 Compose/inspect/日志。主机真实地址可先在聊天里用“NAS 内网地址”代称。
2. **dian115 的版本或镜像标签，以及当前代理实例的播放模式**：代理数据流、重定向/直链或不确定。不确定也可明确留待后续脱敏测试；不要提供云盘 Cookie、激活码或 API key。
3. **fnOS 版本/架构及 FNConnect 是否启用**：用于确定后续 FPK/网关版本条件，不要求现在改变开关或端口。

实际桥接前，再确认同机伴随组件到该 dian115 监听地址的可达性；Host 网络不等于已验证。当前不索要 Emby 原生地址作为回退目标，也不要求改变原 Emby/Docker 网络。

## 收窄后的真实授权与执行顺序

第一阶段只需用户指定上述字段；如需助手检查，单独授权**只读查看对应代理实例入口、监听设置、版本和系统关于页**，不提升账号、不导出配置和凭据。已知当前没有可用 FNConnect Emby 网页，不把“再试一个默认入口”当作下一步。

第二阶段仍须先补齐 fnOS 网关准入/socket 权限、固定打包工具和客户端媒体授权合同。真实包可审阅后，才可批准一个确定 SHA256 的独立伴随组件，仅连接指定 dian115 代理入口；不安装 Emby 插件、不访问 Docker 管理接口、不改 dian115/Emby 配置或公网/路由/防火墙，不创建持久凭据。

第三阶段用户正常 HTTPS 登录专用临时会话，先只读验证经 dian115 的服务器身份，并核对网关/伴随上游确实指向 dian115 代理；仅返回相同 Emby ID 不能证明没有绕过代理。通过后仅用受限 Emby 测试账号、自有测试媒体，允许该账号短时登录/播放会话和进度记录，执行上表矩阵。先观察 dian115 既有重定向决策，再决定任何必要的窄适配；不能为验收擅自切换代理模式。

回退仅退出专用会话，停止/卸载已批准的新伴随组件并清理核对归属的自有目录/socket/profile；原 dian115→Emby 链路、账号、配置和媒体保持。回执仅脱敏状态和哈希；不含原始媒体 URL/账号/凭据。上述真实动作本轮均未执行，非审批拒绝。
