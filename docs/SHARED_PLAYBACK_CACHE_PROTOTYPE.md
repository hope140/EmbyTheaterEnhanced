# 共享视频字节缓存：独立原型

状态：可关闭的本地原型，尚未接入普通客户端，不可据此安排用户验收包。生产播放器、固定内核、认证及 NAS 均未修改。独立基线为 `a5f19c2a981aa65af3f713a1626879f0e1cca971`；历史预载及缓冲导出分支保留。

## 产品合同与实现边界

一份稀疏原始字节存储服务播放缺口、seek、下一集预载和最后播放保留。网络从本地 Range 入口经过，不反向导出 mpv packet，不再推进定制内核。mpv 必需的运行时解复用／解码内存仍存在；共享磁盘不是整份媒体镜像常驻内存。

已确认的目标是当前／最后播放磁盘窗口 M 沿用既有视频缓冲数值，下一集 P 独立为 100／300／500MB、默认 300MB；磁盘媒体预算为 M+P。预载触发为 50／60／70／80／90%、默认 70%。最后实际播放视频在 Stop／退出后保留，到另一视频实际播放才清理；仅浏览或准备下一集不改变实际播放归属，未播放的下一集退出丢弃。现有 mpv 设置含义保持。

当前仅实现存储／HTTP 原型接口，没有把上述产品选项或进度阈值接到普通页面。`actual()` 是必须由可信播放事件调用的实验接口，不能从浏览／下载完成推断；`preload()` 当前只接收测试显式候选，按预算读头部 80% 和尾部 20%。这个头尾分配是实验策略，尚未证明适用所有容器，不是用户批准的新选项。PlaybackManager 继续拥有 Item、MediaSource、PlaySession 和 next；它们的生产接线尚未完成。

## 当前原型

- [store.cjs](../tools/shared-playback-cache/store.cjs)：身份／版本散列、稀疏有界块、原子索引、当前与下一集角色、实际播放转换、重启恢复、读取租约、损坏丢弃和保守占用记账。删除失败或仍被租约持有的文件不会算作已释放。
- [proxy.cjs](../tools/shared-playback-cache/proxy.cjs)：仅绑定随机 loopback 端口，能力 URL 不落盘；强校验器优先，普通元数据模式显式标记。新 route 的本地命中仍需真实源访问检查；冷读直接边收边播，不等块／索引提交。慢盘写队列满就放弃该块缓存，残块不提交。
- [fixture.cjs](../tools/shared-playback-cache/fixture.cjs)：匿名、可控的本地二进制 HTTP 源。它不是 Emby 授权提供者。

身份包含服务器、账号、Item、MediaSource、资源及表示；持久化只保存散列及数字，不存来源 URL、Cookie 或 Token。原型只允许精确 HTTP(S) 来源与受限 User-Agent，不转发浏览器敏感头，不跟随重定向；严格要求 206、准确 Content-Range／长度和 identity 编码。未知长度、HTTP 200 忽略 Range、转码／直播、跨源 302、真实 dian115／115 鉴权链尚未支持。失败目前表现为局部 HTTP 错误／关闭流；尚未实现普通 app 中一次性重开原 source 的回退协议。

无强校验器时采用媒体库稳定假设：身份、长度和已知修改时间／版本变化即失效。新 route 及 grant 到期需重新取得授权；URL 换签不直接等于媒体变更。**同身份、同长度、同修改时间被替换仍可能读到旧块**，回归已复现，不能称为数学上的内容不可变保证。已知 401／403、长度／已知校验信息变化会停止旧 route 后续命中。生产启用与真实鉴权适配仍须独立评估。

## 内存、并发与阶段限制

媒体捕获／读取预留上限 8MiB，待写复制上限 2MiB，完整捕获作业最多 4 个；该值是工程测试边界，不是新增用户设置。源响应最多 2 个、后台最多 1 个、客户端 body 最多 2 个、源排队最多 4 个。通常单源请求连续读取一个缺口；前台暂停并持续背压至少 20ms 才允许后台使用第二响应，前台恢复先取消并等待后台物理关闭。不是每个块重新取得下载地址。

索引序列化／读取上限 2MiB，条目及块等合计最多 4096 行。当前 256KiB 块加行数限制使媒体实用上限约 1GiB，因此**不能声称已经覆盖现有最大缓冲数值**。每块仍重写整个索引；顺序命中读取已改为每次至多 256KiB，避免同块四次读取／校验；非对齐小读仍可能校验完整块。接近窗口上限时的 CPU、元数据、磁盘写放大和 seek 性能未验证。超出边界只减少缓存，不能扩大预算或限制正常媒体读取。

RSS 包含运行时、allocator、socket 等，8MiB 只是显式管理的媒体预留，不是总进程内存保证；OS 文件页缓存及 mpv 另计。

## 已完成的测量与证据界限

本地 HTTP A/B 使用 Linux x64 云容器、Node v24.18.1、AMD EPYC 9V74（容器报告 5 个逻辑 CPU）、同进程源／代理／客户端、loopback、真实临时文件和未清 OS 页缓存。每项 3 对 warmup、20 对正式样本，AB／BA 交替；阈值在采样前固定，失败不删除。首字节指实际 body 字节，不是 HTTP header／首帧。冷读及缺口 p50 新增不超过 10ms、p95 不超过 25ms；限速吞吐比不低于 90%。无节流 loopback 在采样前列为独立诊断，仍公开其退步。

校正边界样本并修复回归后的定稿重复测量（每项仍为 20 对，早期原件保留）：

| 项目 | 观测 |
| --- | --- |
| 冷读首字节新增 | p50 1.20ms，p95 2.32ms |
| 远缺口首字节新增 | p50 0.47ms，p95 1.46ms |
| 稳态命中首字节中位数 | 直连 21.06ms，缓存 1.28ms |
| 新 route 命中，含真实访问探测 | 新增 p50 0.41ms，p95 1.91ms |
| 约 8MiB/s 合成限速源冷读吞吐 | 中位数为直连的 99.8% |
| 无节流 loopback 冷读吞吐 | 中位数为直连的 49.7%，不能隐去或泛称无开销 |

缓存／缺口边界每次重新准备并确认一半命中、一半回源；第一轮该项被首次样本填满，后续样本无效，原回执保留但不作结论。正常关闭后源、客户端、媒体预留和读取租约均为零。测试源不含用户数据，没有接触 115。

独立进程内存重复小负载：源与客户端均在测量进程外，8MiB 文件重复读取并预载 1MiB；定稿这一轮仅代理转发峰值 RSS 59,240,448B，启用缓存 67,629,056B，差约 8MiB，前一轮差约 10.1MiB。缓存显式媒体预留峰值 2MiB，两进程都关闭并退出。测试当前／下一集磁盘窗口为 8／1MiB、媒体内存预留为 2MiB、待写为 512KiB，不能混称产品 M／P。2ms 采样可能漏短峰；顺序少量测量、较小缓存、allocator／socket 差异不能证明最大产品窗口的固定 RAM。定稿回执绑定实际 Node、源码及合成输入哈希。

Linux 标准 libmpv C API 软件离屏解码仅使用本机已有实验库，不重编、不使用自定义导出 API。小压缩片两路首帧及 seek 目标 RGB 相同，seek 前后画面不同。早期探针有两个错误：time-pos 更新后误收旧帧，以及在渲染线程同步查询属性，触发已复现的 200ms VO 等待并丢帧。现已遵循固定 [render.h 线程合同](https://github.com/mpv-player/mpv/blob/dd5d17d3285a095a0f712fa9d116e22a076492de/include/mpv/render.h)，采用异步命令、属性观察和非阻塞事件读取；旧轮的无效 timing 保留，不计验收。

修正后 raw NUT 合成源共 8 秒、9,074,583B，160×90 离屏软件 RGB，音频关闭。测试 mpv 前向窗口 1MiB、后向 256KiB，磁盘 M=16MiB、P=1MiB，均仅为压力测试值。每组 3 对 warmup、20 对正式样本，AB／BA 交替；两路首帧及目标帧 RGB 一致，目标帧与起始帧不同，所有进程正常退出、上下文终止、资源清零，无代码漂移。

| raw 视频路径 | 直连 p50 | 原型 p50 | 判定 |
| --- | --- | --- | --- |
| 冷缓存首个解码帧 | 294.88ms | 187.01ms | 首帧更早 |
| 上述首帧后立即 seek 到 3 秒 | 127.02ms | 248.04ms | 新增 p50 121.51ms、p95 124.31ms，未通过 |
| 完整暖盘、新 route、含访问探测首帧 | 295.08ms | 40.52ms | 本条件通过 |
| 完整暖盘 seek 到 3 秒 | 126.72ms | 5.76ms | 本条件通过 |

暖盘在每块准备后等待提交并验证完整覆盖；不能把高速整文件准备时主动跳过的写入当作已完整缓存。冷样本之间清理各自测试对象，防止逐步变成近满窗口测试。这里测量 load／seek 到解码 RGB，非实际屏幕呈现，也不包括普通 app 登录／取源耗时。

当前证据定位到一个性能代价：先读缓存前缀使首帧提前，但 demux 可能马上阻塞在新缺口的网络读取；随即 seek 仍需等待读取收尾。为此只在实验接口中试了旧前台读取快照取消：先提交既有异步 seek，收到固定内核 SEEK 事件再取消旧快照，不影响新请求、缓存、授权或下一集。合成链保持可解码／可继续，但冷 seek 仍约 256.49ms，对比直连 126.54ms，且每次源请求由 5 增至 6。该尝试**无收益，不应接入普通 app**；不能靠延长超时、保留已取消下载或隐藏首帧来改判。

库来源是此前独立实验构建，虽然本轮只用标准 C API，它仍不等于固定 Windows 产品库；上述结果不能推广到 Windows／gpu-next、任意影片、音轨字幕或真实服务器。

尚未完成：普通 app 可信授权／播放实际开始接线、自然下一集进度链、最大窗口性能、Windows 首帧／seek／卡顿／内存、真实容器尾索引与音轨字幕，以及已获允许之后的有限真实来源检查。未通过这些之前不建议打用户验收包。

## 复现与下一阶段门禁

工具只用 Node 内置模块；原始回执保存在调用者提供的全新私有目录，不进仓库。使用项目固定 Node，分别顺序执行，不与其它性能负载并行：

```sh
node --test tests/shared-playback-store.test.cjs tests/shared-playback-proxy.test.cjs
node tools/shared-playback-cache/benchmark.cjs --run --out "$PRIVATE_FRESH_OUTPUT"
node tools/shared-playback-cache/memory.cjs --run --out "$PRIVATE_OTHER_FRESH_OUTPUT"
node tools/shared-playback-cache/native-ab.cjs --run --out "$PRIVATE_NATIVE_OUTPUT" \
  --variant raw --media "$OWNED_FIXED_RAW_NUT" --library "$IDENTIFIED_EXISTING_LINUX_LIBRARY"
```

`native-ab` 验证固定合成输入 SHA，库 SHA 在 `native-frame.py` 固定；若材料缺失应报告缺失，不下载旧包、替换身份或自动构建新内核。性能门禁失败时保留样本并定位，不放宽阈值。下一步应先解决本地真实 seek 失败及性能开销，再讨论普通 app 接线；不反复对真实 115 发请求。


固定合成输入的生成配方使用已安装 FFmpeg，禁止自动获取工具／内核。原输入 SHA 已在 `native-ab.cjs` 锁定；生成工具版本差异可能改变容器字节，需独立记录版本与新身份，不可静默替换固定输入：

```sh
ffmpeg -v error -nostdin -f lavfi -i 'testsrc2=size=160x90:rate=24:duration=8' \
  -f lavfi -i 'aevalsrc=0.2*sin(2*PI*(431*t+20*t*t)):s=48000:d=8' \
  -map 0:v -map 1:a -c:v rawvideo -pix_fmt bgr24 -threads 1 -c:a pcm_s16le "$OWNED_NEW_FIXTURE_DIR/raw.nut"
```

压缩 MP4 配方另加第二条 `aevalsrc=0.2*sin(2*PI*(709*t+13*t*t)):s=48000:d=8`，映射 `2:a`，视频参数 `-c:v libx264 -pix_fmt yuv420p -preset fast -bf 2 -g 24 -threads 1`、音频 `-c:a aac`；两个历史输入的生成时版本未完整记录，本轮只验证现有字节身份，未声称已重新生成相同 SHA。

结论：同一份字节供预载／播放／重启保留的基础成立；性能验收仍失败，暂不接入或打包。最小后续工程应针对“部分命中连续读 + 立即 seek”的前台 IO 策略，固定首帧／目标帧与请求数作比较，先验证不会诱发重新连接旧位置；不再扩充取消提示协议。随后才是普通入口可信身份与会话接线、最大窗口索引成本及 Windows 原生验证。
