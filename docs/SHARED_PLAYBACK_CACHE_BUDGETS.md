# 共享缓存：吞吐预算与真实落盘边界

后续索引迭代已解决本页记录的1GiB截断与逐块全量重写，见[增量索引验证](SHARED_PLAYBACK_CACHE_INDEX.md)。本页保留 bd45926 阶段的历史测量；吞吐与默认队列结论未撤销。

范围：experiment/shared-playback-cache 的独立本地原型。只使用自有合成数据；未改默认缓存预算、前缀复用／seek 策略、客户端配置或生产内核，未访问真实外部媒体。没有打包、安装或发布。此前首帧／seek 条件和未通过项仍见[原型说明](SHARED_PLAYBACK_CACHE_PROTOTYPE.md)。

## 是否需要为吞吐比例扩大队列

本轮不以无节流百分比作为无限优化目标。此前 20 对同进程分项中完整路径为 344–645MB/s，即约 2753–5158Mbps，虽然只有直连 56%–59%，绝对值远高于 100／200Mbps。该数字不是影片码率保证；本轮用隔离代理进程重新测量，并增加约 250Mbps 限速源。

结果：限速矩阵中缓存首读实际 29.14–30.72MB/s，即 233.1–245.8Mbps；同轮直连源约 238.8–255.2Mbps。本地输送在本次 100／200Mbps 参考量级上未显示主要瓶颈，不能推导实际播放器无卡顿、真实 TLS／NAS 或任意码率均无退化。100／200Mbps 仅是工程比较值，没有新增用户设置。无节流新进程首读波动大，三次最慢缓存样本 82.63MB/s（661Mbps），与先前热分项不是同一口径。

**不增加默认内存。** 16／32MiB 预留未带来可归因的限速收益；固定 8 个捕获作业和 2MiB 待写复制限制下，实际媒体预留最多 4MiB。更大上限没有变成更大常驻缓存，也不能从无节流三次差值宣称增大队列提速。当前主要产品阻碍转为大窗口索引，而非追逐内存源极限比例。

## 测试条件与口径

- Linux x64 云容器，Node v24.18.1，AMD EPYC 9V74；本轮 availableParallelism 为 4，容器总内存约 18GB。负载顺序执行，没有与 native／其它性能实验并跑。
- 数据源为 8MiB 固定二进制内存源；源和收集响应的客户端在父进程，单个新子进程只拥有代理／存储。无 TLS、无解码／屏幕呈现。每 GET 校验实际字节及 SHA。
- 存储为容器 overlay 文件系统的真实临时文件，底层设备类型／共享宿主负载未知；OS 页缓存未清。完成 writeFile／rename 不等于设备持久化吞吐，本轮不作 HDD、SSD 或掉电持久性保证。
- B 表示代理显式媒体预留上限，不是 RSS。B 为 1／4／8／16／32MiB，待写上限为 min(B/2, 2MiB)，8 个完整作业保持不变。默认仍为 B=8MiB／待写=2MiB。
- 每档各三次全新子进程，两臂按次数交替。每对 worker 前直连源读一次，记录作参考；不是原生 AB／BA 首帧门禁。每 worker 完成首读 8MiB、重复读 8MiB、预载 1MiB、读取下一集 256KiB；磁盘测试 M=8MiB、P=1MiB，不冒充产品 M／P。
- 无节流源每次最多发送 64KiB；限速源每 64KiB 等待 2ms，名义 262.144Mbps，实际速率另报。请求 duration 到响应 end，不含后续哈希计算；没有将计划 Range 或写回调当作接收正文。
- 下表吞吐为三次中位数，RSS 为三个 worker 的最大采样峰值，显式预留为观测峰值，逻辑写入为工作负载累计三次中位数。2ms 内存采样可能漏短峰，没有三样本 p95 承诺。

D／F／C 分别为直连、仅代理转发、启用缓存。MB/s 和 Mbps 为十进制；MiB 为 1048576 字节。

## 真盘 M+P 与最大窗口

[quota.cjs](../tools/shared-playback-cache/quota.cjs) 使用唯一 256KiB 合成 Buffer，代表 4GiB 逻辑来源，逐块真实写文件；没有分配整片 Buffer、下载或播放。两个固定场景共约 26.47 秒，显式上限 300 秒；每个操作核对记账，阶段再核实际文件、索引、临时文件与已完成逻辑写入。

| 场景 | 实际结果 |
| --- | --- |
| M=300MiB、P=100MiB | 真实填满 400MiB payload，峰值 419430400B；媒体索引 469242B，目录内文件逻辑长度合计 419899671B（文件系统报告分配 419905536B），临时文件 0 |
| 各角色超一块 | 两次拒写；原有回收策略各淘汰一块后停止，没有超过 M+P |
| Stop／重开 | 仅实际 A 的 299.75MiB 保留，未播 B 的 99.75MiB 删除；准备 C 不清 A，actual(C) 才删 A，留下 C 一块 |
| 配置 M=3072MiB、P=500MiB | 行数保护在 4095 行处拒写；最高 payload 1023.25MiB，排空回收后 A 留 1023MiB，P 未填满；不是支持 3GiB |
| 最大场景重开／切片 | A 恢复、旧 B 丢弃、准备 C 保留 A、actual(C) 清 A；最终只留 C 256KiB，无临时文件 |

M+P 是**媒体 payload 合计**硬上限，包含未释放租约、已退休块、孤儿文件与待写预留；目录还需加索引／owner／临时索引。角色迁移期间，仍被读取持有的旧块可能被重分类而使某单角色暂超 M 或 P，总额不能因此释放额度。本轮修复 put 在复制／预留前的全局 admission；两个确定性修前红例分别覆盖 open 迁移与 actual 迁移，修后拒绝借旧租约再次写入另一窗口。正常顺序真盘场景同时核各角色上限，不将其泛称租约瞬态不变量。

### 大窗口的实际代价

| 场景 | 完成媒体逻辑写入 | 完成索引逻辑写入 | 探针观测 RSS 峰值 | 耗时 |
| --- | --- | --- | --- | --- |
| 300／100MiB | 419692544B（含最后 C 一块） | 379669672B | 143757312B（137.10MiB） | 5.40s |
| 3072／500MiB，遇行数限制 | 1073479680B | 2474287133B | 207171584B（197.57MiB） | 21.07s |

这里每块仍全量序列化／重写索引。最大场景写入约 1.073GB 媒体，却累计写入约 2.474GB 索引；索引最终仅约 1.203MB。RSS 采样在操作边界，不是完整时刻最大值；第二场景同进程执行，allocator 历史与整索引重建均计入，不是纯代理队列内存，也不能承诺产品低峰值。

因此**不能仅上调 4096 行上限**就宣布 3072MiB 选项可用；会扩大整索引写放大与 GC 压力。真正支持最大窗口至少需有界增量／分段索引及独立迁移／损坏恢复验证，再保持 M+P、读取租约和前台旁路合同。该工程尚未实施。本轮没有为吞吐比例扩大内存或改变已验证的稀疏策略。
