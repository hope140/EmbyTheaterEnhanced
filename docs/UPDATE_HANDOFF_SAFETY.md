## 退出归属

所有重复退出共用唯一drain，完成前每次before-quit都被阻止。更新退出期间的窗口关闭也进入同一owner，避免超时提示后失去窗口。30秒是观察期限，不代表pending工作已取消；关键失败／超时阻止安装放行，记录固定pending／failed阶段并提示，不强杀Electron／Host、不使用app.exit。超时后实际完成的工作只允许下一次明确退出请求复用，不重复清理。

| 步骤 | 归属与失败策略 |
| --- | --- |
| 电源、诊断IPC | 同步释放，无独立进程或持久写入；异常仅记录，仍等待其他工作。 |
| 更新、通道、缓存 | 等原active请求、偏好保存与本地对账；update lease单独管理。 |
| HTTP缓存 | 等不能物理取消的clear/read结算，不把请求取消当作物理完成。 |
| 下载、STRM、CD2 | 保留原取消／暂停、文件收尾、注销与transport close；异常保守阻止放行。 |
| 刷新率 | 保留原工具归属、取消与实际退出观察，不按进程名操作。 |
| Native Helper | 等startup、所属child实际退出、预览和surface释放，不以transport error代替exit。 |
| 内核、Windows媒体、启动 | 等原worker、队列／frame／session及启动Promise；文件选择器保留原退休策略。 |

关键工作仍不确定时保持关闭状态，不能恢复已经注销的业务能力；永久失败需要保留诊断并人工恢复应用。候选没有增加整体强退策略。

## 两阶段交接

READY保持原目录／安装器／Zone／哈希锁；commit／ARMED只代表准备退出，此时仍持有认证pipe并允许取消。关键drain实际完成后，main才请求launch；确认RELEASED后才脱离relay并正常退出。迟到确认不能放行。守卫随后等待捕获的Electron及同目录Host真实句柄和零退出码，合计最多120秒，再通过原UseShellExecute无参数打开可见向导，保留系统安全检查。

准备限30秒，ARMED及最终放行各限5秒，守卫等launch最多60秒。取消只针对尚未放行的所属guard／relay；观察实际退出最多5秒，到期返回handoff-cancel-unconfirmed并保留owner、禁止再次创建guard，直到观察到实际退出。放行后不声称取消成功。

更新IPC注销先等待active请求返回，再观察所有取消未确认的guard实际退出；active返回错误不等于后台guard已经释放。这个观察继续属于关键drain，整体期限到达只报告阻塞，不借请求错误越过实际退出。多个尝试的恢复提示与摘要按最近有效回执排序，旧的cancelled记录不能盖过新的待确认交接。

原生guard持有按规范化executable哈希派生的本地互斥，覆盖同一安装位置不同尝试；忙或abandoned状态失败关闭。仍记录shell-entered／shell-started的任何旧尝试也阻止另一尝试，不能把未知安装器状态当作取消。

## 持久回执与恢复

main在专用updates根预建随机尝试绑定的handoff JSON，置于安装器子目录外。JS拒绝符号链接、多硬链接、身份替换与超限内容；guard按卷／文件ID打开同一文件并持有排他写句柄、同步flush。活动guard的回执不能被重试覆盖。目标版本在原executable位置实际启动并安全清理后，才删除已知对应回执。

回执仅含schema、固定stage、有限elapsedMs／exitCode；区分等待放行、Electron／Host等待及超时／非零退出、ShellExecute进入／实际返回句柄、向导退出与启动失败。无URL、令牌、路径、进程名、命令和原始异常；读端重新投影，损坏或部分写入只记不可用，不能成为执行授权。启动将有限摘要和匿名attemptId并入原诊断日志，关于页显示恢复提示。

shell-started不等于安装完成，wizard-exited（包括退出码0）不等于升级成功；确认仍依实际应用版本与原安装位置。只有实际guard退出后才记录cancelled。每次明确重试仍从官方Tag重核身份，再检查物理文件身份与完整SHA：好包复用，坏包保留并另建尝试下载校验，不删除或接管未知文件。不确定的guard／安装器保持阻止，不能通过忽略锁或强杀来重试。

## 验证与升级边界

定向回归使用真实main摘录、EventEmitter、可控Promise／时钟、IPC模拟和临时非可执行文件；隔离Windows job验证实际句柄、写锁／互斥和marker-only退出链，不调用受控安装器入口。准确源码与结果见[维护记录](DEVELOPMENT_LOG.md)，Linux、Windows原生与可见安装分别报告。

修复只在含候选的新客户端运行时生效。旧客户端升级到新版本的那一次仍执行旧客户端的退出／交接逻辑，不能追溯修复旧进程已发起的交接。
