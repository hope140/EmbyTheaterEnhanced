# Seek／片头结束异常调查候选

本候选基于 v0.4.9 的播放实现，修复可控模拟已确认的片头归属与边界缺陷，并补充普通 Seek／EOF 诊断。它没有证明实际媒体在普通拖动后结束的根因，也不表示新的 Windows 安装包或真实服务验收已完成。

## 已确认的片头缺陷与修复

切集时旧 `currentIntroInfo` 曾保留到新资料成功返回；新资料延迟或失败期间，旧片头终点可以作用到新媒体。另一个独立问题是片头功能验证 Promise 尚未返回时切集，旧点击会读取并跳过新媒体的片头。片头终点达到或超过片长也曾直接传给播放器。

OSD overlay 现在在播放／媒体替换、停止、释放和视图退出时清除片头状态，绑定播放器、媒体、账户及会话上下文，并在异步点击完成时再次核对上下文与独立片头代次。片头起止必须是有限数值，满足 `0 <= start < end < duration`；不把坏终点裁成片尾。

ETE 的片头检查只接受当前原生代次与当前播放请求共同拥有的正时长。新时长尚未到达时，片头入口等待，不复用上一集的缓存或以媒体元数据替代。其它播放器保留当前 MediaSource、PlaybackManager 时长的兼容路径。原有 IntroStart 后取下一章节终点的解析兼容行为保持；日志区分明确 IntroEnd 与下一章节来源。

## 新日志的含义

| 事件／字段 | 含义与限制 |
| --- | --- |
| `seek-command-submitted` | 当前请求的定位意图；含每播放请求独立的 `sequence`、绝对／相对模式、秒单位目标及提交前缓存快照。 |
| `seek-command-accepted`／`failed` | bridge 接收结果，保留同一定位序号和提交时快照；接收不等于已落点或媒体可读。 |
| `seekOrigin` | 固定枚举：片头按钮、自动片头、进度条、远控 Playstate、相对控制或未知来源。 |
| 片头字段 | 起止 ticks、片头／点击归属是否匹配、终点来源、验证时长和时长来源；不记录账户、Item、Session 或章节正文。 |
| `intro-skip` | 点击重新验证后的拒绝／不可用结果；不在每次 timeupdate 或隐藏按钮检查时刷日志。成功定位由 Seek 提交记录携带同样片头字段。 |
| `seek` | 既有原生 playback-restart 观测，附原生位置、事件代次和归属。原生 Seek 通知与重启通知不能据此换算为用户操作次数。 |
| `latestSubmittedSeek` | 此播放请求最近一次提交的定位摘要，标明 `latest-submission-only`；不是原生完成事件与命令的一一匹配。 |
| `stopSource=native-eof-reached` | 保留原自动停止行为；补充事件代次、最近定位和位置／时长／缓存快照，不把它解释为已证实的正常片尾或网络原因。 |
| `loadfile-requested` | 起播请求秒数、计划写入的整秒 start 和实际代码顺序；`plannedStartSeconds` 不表示原生已经应用。 |

位置、时长、缓存状态和缓存时间都带其观测代次及 `CurrentGeneration`。`true` 表示已匹配当前请求与原生代次，`false` 表示不匹配，`null` 表示无法确认。helper 重启后复用同一数字代次，也不能把上一播放的缓存判成当前。MediaSource／Item 的声明时长另外记录，便于比较进度条计算依据与原生观测。

日志只投影有限数值、布尔值和固定枚举，仍经过现有统一脱敏器；不记录完整播放 URL、令牌、原始命令、服务器响应或任意上下文对象。只保存最近一次定位摘要，提交／应答／完成／结束时写日志，不新增原生查询或高频属性日志。诊断发送失败不阻断播放。远程播放器自行处理 Seek 或不支持直接 Seek 而重新取流的路径，未承诺透传本地诊断上下文。

## 仍未证实的普通 Seek 根因

普通进度条按 PlaybackManager 当前时长计算目标，非 OSD 旧显示时长。可控模拟确认：媒体声明时长明显大于真实媒体时长，或新媒体未提供时长而原生仍有旧缓存时，可能算出超出真实片尾的目标；尚无现场目标与两种时长证明实际发生了这些条件。本候选不改变普通 Seek 的计算、命令、完成通知、EOF 处理或 `loadfile` 后写全局 `start` 的既有顺序。

固定 mpv 源码说明部分解复用读取失败可折算成 EOF；单纯缓存暂时为空会等待，不能据此归因某个代理、服务器或缓存实现。主进程已有过期代次丢弃；直接绕过主进程注入 renderer 旧 EOF 的模拟不证明真实 IPC 会发生同样重排。调查未找到足够证据修改这些播放行为。

## 验证层级

定向测试执行真实冻结 Web 源的 overlay、PlaybackManager 与输入 API 接线、adapter／client 和合成 IPC，覆盖延迟／失败资料、旧点击、新旧代次、同数字代次重用、合法与越界片头、原定位单位与参数、应答反序、失败日志隔离，以及真实脱敏器的敏感字段拒绝。原 overlay 哈希、构建输入与来源篡改门禁同步更新，vendor 原文不变。

这些测试不替代固定 Windows native 栈、实际片源、GUI 或网络验收。具体公开集与材料集结果记入[维护记录](DEVELOPMENT_LOG.md)；候选保持独立分支，等待与下一测试版整合，不单独发布。
